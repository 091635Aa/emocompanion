# 一体化全流程 AI 应用 Spec（build-integrated-fullflow-app）

## Why

用户需要把分散在多个目录的现有资产（`f:\打标` 打标系统、`f:\lora外挂` LoRA 微调、语义回响推理引擎、`f:\最终工程架构` 全流程推理）整合为一个**从零数据样本 → 下载模型 → 打标 → 微调 → 日记 → 达标 → 推理架构 → 最终使用**的一体化应用，落地于全新空目录 `j:\最后版本！`。应用须支持设备自动适配（CUDA/显存/内存检测与预估、自动下载，明确不支持 AMD）、高度自定义（所有模块输入/输出/格式/时间可配置）、前端 FastAPI + Web 页面，并交付**本机测试版**与**发行版（GitHub）**两个版本。

## What Changes

- 在 `j:\最后版本！` 从零搭建一体化全流程应用（Python 后端 + FastAPI + Web 前端）。
- 复用现有资产而非重写：
  - `f:\打标`：打标流水线、二次复核、看板经验（打标引擎）
  - `f:\lora外挂\training_scripts`：LoRA/QLoRA 微调脚本（微调引擎底座）
  - 语义回响引擎（`i:\Desktop\语义回响\semantic_echo`）：推理架构（V1 简单回响 / V 通用四层）
  - `f:\最终工程架构\API服务`：FastAPI + 静态 Web 页面的既有模式
- 新增能力：
  - **数据预处理**：音频/视频/文本三种输入，自动清洗，**按话题分割片段**（非按时间）
  - **音频转文本（ASR）**：由用户配置的全模态模型（需音频解码器，如 Qwen 全模态系列）完成音频→文本
  - **打标引擎**：复用现有打标逻辑，产出微调数据包（可导出给用户自用）
  - **日记生成（全新板块）**：结合打标数据与音视频画面目录，通过与本地大模型（用户配置，如 30B 千问）对话，伪造**超长期日记**（可从 7 岁起逐年累积，每篇数百~数千字），作为身份微调的核心文本
  - **三维度微调**（每个维度可勾选/取消/选择）：
    1. 情感表达微调（普通打标数据）
    2. 记忆微调（日记数据）
    3. 身份微调（告诉模型"它是真人"，去除 AI 味 —— **用户新提出的方向，需先做可行性验证**）
  - **微调引擎**：自动适配显卡（CUDA 检测、显存检测与预估、内存检测、自动下载依赖），自动识别模型架构（Qwen 系列等）并选择 LoRA/QLoRA 与思考能力检测（如 Qwen3 think 模式），微调文本结构化、避免乱码
  - **模型管理**：模型下载镜像源可选（魔搭社区 ModelScope 等），加载后做性能评估（显存占用、能否推理、能否微调），基座模型用户自选
  - **达标评估**：微调后跑图灵测试式判定（具体算法由实现方确定，如中文体系图灵检测 + 角色保真）
  - **推理架构**：V 通用架构（语义回响 + LoRA + RAG + 记忆）与 V1 简单回响两种，λ/γ/τ 等参数可自动推荐或自定义，含记忆外挂
  - **定制模型组织**：支持"一角色一模型（1:1）"与"三维合一单模型"两种，前端可选；单模型承载多记忆属实验性，前端需勾选确认 + 警告弹窗
- **高度自定义**：所有模块的输入、输出、输出时间、格式均提供配置项。
- **交付**：本机测试版（一键启动）+ 发行版（打包脚本 + 发布到 GitHub）。
- **约束**：仅支持 NVIDIA CUDA，不支持 AMD。

## Impact

- Affected specs：无既有 spec 匹配（全新项目）。
- Affected code：`j:\最后版本！` 全部为新代码；复用外部目录仅**读取/导入**，不修改 `f:\打标`、`f:\lora外挂`、`i:\Desktop\语义回响\semantic_echo`、`f:\最终工程架构` 现有文件。
- Affected data：`j:\最后版本！\数据\`（上传、分割片段、打标结果、日记、微调数据包、微调输出、模型库）。

## ADDED Requirements

### Requirement: 项目骨架与一键启动
系统 SHALL 在 `j:\最后版本！` 建立分层目录（配置/核心引擎/前端/数据/测试/发行版），提供本机一键启动入口（`启动.py`），自动检测并提示缺依赖。

#### Scenario: 首次启动
- **WHEN** 用户运行 `启动.py`
- **THEN** 自动检查 Python 版本与依赖，缺失时提示安装命令；随后启动 FastAPI 服务并打开 Web 页面。

### Requirement: 硬件检测与设备适配
系统 SHALL 自动检测并预估硬件能力：
- CUDA 是否可用、CUDA 版本、GPU 型号与驱动版本
- 显存总量/可用量，按模型参数量 + 量化档位预估推理/微调所需显存
- 系统内存总量/可用量
- 不满足时给出明确提示（**不支持 AMD**，仅 NVIDIA CUDA）

#### Scenario: 显存预估
- **WHEN** 用户选择某个模型 + 量化档位（fp16/4bit）
- **THEN** 前端显示预估显存需求与是否可在本机运行、是否可微调。

### Requirement: 配置系统（高度自定义）
系统 SHALL 提供全局配置文件（JSON），覆盖所有模块的输入/输出/格式/时间等自定义项，Web 前端提供可视化编辑界面，修改即时生效（或提示重启生效）。

#### Scenario: 自定义输出
- **WHEN** 用户修改日记输出目录、日记篇数字数、微调轮数、输出格式等配置
- **THEN** 对应模块按新配置执行，不硬编码。

### Requirement: 数据输入与预处理（话题分割）
系统 SHALL 支持三种数据输入（视频微调 / 音频微调 / 文本微调）：
- 上传后自动清洗（去噪、去重复、格式统一）
- 音频/视频**按话题分割**为片段（非简单按时长切分；需基于内容聚类/转写后语义分段）
- 分割结果可视化预览，用户可微调边界

#### Scenario: 话题分割
- **WHEN** 用户上传一段直播回放视频并勾选"开启视频解析"
- **THEN** 系统自动转写并按话题切分为多个片段，前端展示每个片段的话题摘要与时长。

### Requirement: 音频转文本（ASR）
系统 SHALL 调用用户配置的全模态模型（具备音频解码器）完成音频/视频→文本，支持批量处理、断点续转，输出结构化转写文本（含时间戳、说话人可选项）。

### Requirement: 打标引擎
系统 SHALL 复用 `f:\打标` 打标能力，对每个片段自动打标（情感维度/内容标签/风格等），支持人工复核，产出**微调数据包**（JSON/JSONL，可导出给用户自用）。

#### Scenario: 导出微调数据包
- **WHEN** 打标完成且用户点击导出
- **THEN** 生成结构化微调数据包（含 instruction/response 或对话格式 + 标签），并可一键送入微调模块。

### Requirement: 日记生成（全新板块）
系统 SHALL 提供日记生成模块：
- 输入：打标数据 + 音视频画面目录（用户选择）
- 通过与本地大模型（用户配置，可 30B 千问）多轮对话，生成角色**超长期日记**（可从 7 岁起逐年累积，每篇数百~数千字）
- 日记内容作为身份微调的核心文本（让模型"觉得自己是真人"）
- 支持人工审阅、修改、补充人设
- 所有生成参数（起始年龄、篇数、字数、风格）可配置

#### Scenario: 生成伪造记忆
- **WHEN** 用户选择音视频目录并点击"生成日记"
- **THEN** 系统与本地大模型对话，产出从 7 岁到当前的连续日记序列，保存到配置的日记目录，并可供微调模块勾选引用。

### Requirement: 三维度微调引擎
系统 SHALL 支持三个微调维度，每个维度可勾选/取消/选择：
1. 情感表达微调（打标数据）
2. 记忆微调（日记数据）
3. 身份微调（真人身份文本）
- 自动检测模型架构（Qwen2.5/Qwen3 等）与思考能力（如 Qwen3 think 标记），选择对应 chat 模板与训练策略
- 自动选择 LoRA（fp16）或 QLoRA（4bit）以适配显存
- 微调文本结构化处理，避免乱码（统一编码、清洗控制字符）
- 微调日志与断点、产物落盘到 `数据\微调输出\`

#### Scenario: 身份微调可行性验证
- **WHEN** 实现阶段先运行一个小样本实验（身份微调方向）
- **THEN** 输出可行性报告（微调后模型是否更"像真人"、是否出现格式退化），据此决定该维度默认建议。

#### Scenario: 组合微调
- **WHEN** 用户勾选情感 + 日记 + 身份三个维度并选择基座模型
- **THEN** 系统混合数据训练，输出定制模型，并记录各维度数据占比。

### Requirement: 模型管理
系统 SHALL 提供模型管理：
- 本地模型扫描（模型目录、型号、参数量、架构、量化档位）
- 在线下载（镜像源可选：魔搭社区 ModelScope / 其他，支持断点续传）
- 加载后性能评估（显存占用、生成速度、能否推理、能否微调），输出评估报告

#### Scenario: 下载模型
- **WHEN** 用户选择模型 ID + 镜像源 + 量化档位点击下载
- **THEN** 系统自动下载到模型库并登记，随后可一键性能评估。

### Requirement: 微调产出模型组织
系统 SHALL 支持两种产出组织方式（前端可勾选）：
- 一角色一模型（1:1）：每个角色独立微调出专属模型/适配器，推理时按角色切换
- 三维合一单模型：多个维度合并训练为一个统一模型
- 单模型承载多记忆（实验性）：前端标注"不推荐"，选择时需勾选确认并弹出警告弹窗

### Requirement: 达标评估
系统 SHALL 在微调后运行达标评估（图灵测试式判定，算法由实现方确定）：
- 输出每项得分、综合均分与《达标报告.md》
- 未达标时如实记录差距与分析

### Requirement: 推理架构（V / V1）
系统 SHALL 提供推理架构层：
- **V1 架构**：语义回响简单注入（复用 `semantic_echo` 回响池 + 采样处理器）
- **V 通用架构**：语义回响 + LoRA + RAG + 记忆四层，按需激活
- λ/γ/τ 等参数：自动推荐（扫描表/公式/架构族因子）或用户自定义
- 支持记忆外挂（持久化记忆文件，跨会话生效）
- 加载微调产出模型（适配器/定制模型）作为推理基座或附加层

#### Scenario: 通用架构推理
- **WHEN** 用户选择 V 架构、加载定制模型与记忆外挂、输入提示词
- **THEN** 输出带情感增强的回复 + 指标（语义熵/重复率/情感命中率/耗时/显存）。

### Requirement: Web 前端
系统 SHALL 提供 FastAPI + Web 页面，页面包含：
- 仪表盘（硬件状态、任务进度）
- 数据预处理页（上传、话题分割、ASR）
- 打标页（片段打标、人工复核、导出数据包）
- 日记生成页（30B 教师对话、日记审阅）
- 微调页（三维度勾选、基座选择、训练控制）
- 模型管理页（本地扫描、下载、性能评估）
- 推理页（V/V1 选择、参数定制、聊天演示）
- 达标评估页（结果报告展示）
- 配置页（高度自定义项编辑）
- 所有"实验性"选项（如单模型多记忆）带警告弹窗确认

#### Scenario: 微调页勾选
- **WHEN** 用户在微调页勾选"身份微调"并取消"记忆微调"
- **THEN** 训练数据仅包含情感 + 身份维度，前端提示本次组合内容。

### Requirement: 全流程编排与测试
系统 SHALL 提供全流程一键编排（各模块可独立运行，也可串联），并提供冒烟测试与全流程测试脚本：
- 冒烟测试：最小链路（文本输入 → 微调数据包 → 微调 → 推理）可跑通
- 全流程测试：真实链路（视频/音频 → 话题分割 → ASR → 打标 → 日记 → 微调 → 达标 → 推理）执行并输出测试报告

### Requirement: 发行版打包
系统 SHALL 提供发行版：
- 打包脚本（依赖清单、启动器、配置模板、README）
- 发布指引（上传 GitHub 仓库的步骤说明）
- 本机测试版与发行版共用同一核心引擎
