### 3.2 V1 回响引擎对比（裸生成 vs 回响生成）

λ=0.08 / γ=0.07 / τ=0.09，max_new=80，Qwen2.5-0.5B：

| 指标 | 裸生成 | 回响生成 | 变化 |
|---|---|---|---|
| 平均语义熵 | 4.206 | 2.273 | **-46%** |
| 平均重复率 | 0.002 | 0.088 | 上升 |
| 单条耗时 | 2-4s | 21-36s | 慢 ~8-10 倍 |

**重要发现**：在 0.5B 基座 + λ=0.08 配置下，回响注入使语义熵下降、重复率上升，且逐 token Python 循环使生成显著变慢。**说明回响参数需按模型校准**（0.5B 的扫描表推荐 λ=0.50；λ=0.08 是 1.5B 档位），且 V1 引擎的逐 token 生成循环有性能优化空间（如 CUDA graph / 批量前向）。该结论与语义回响项目多模型对照实验的"λ 需按 hidden_dim 与架构族校准"一致。

| 项目 | 实测 |

**实现要点**：
- Qwen2.5-Omni-7B 仅兼容 transformers 4.5x（config 标注 4.50.0.dev0），主环境为 5.14 → 建立独立环境 `.venv_asr`（`--system-site-packages` + `transformers==4.54.1`）
- ASR 通过独立进程 `核心引擎\asr转写worker.py` 执行（`数据预处理.音频转文本` 以 subprocess 调用），避免版本冲突
- 全模态模型原生加载存在 CUDA 驱动级偶发崩溃（0xC0000005，非代码缺陷），已内置自动重试兜底（实测首试崩溃、重试即成功）

## 七、已知限制与待办

1. **V1 回响参数需校准**：0.5B 下 λ=0.08 效果为负，建议正式使用按模型档位选用扫描表值（0.5B→0.50，1.5B→0.08，3B→0.10）
2. **V1 生成性能优化**：逐 token Python 循环慢，建议后续批量前向或 CUDA graph 优化
3. **0.5B 基座生成质量有限**：正式使用建议 3B/7B/定制模型
4. **教师模型未接入**：日记生成当前走降级模板；配置 `模型.教师模型` 指向本地大模型后走真实生成
5. **ASR 环境依赖**：首次使用 ASR 需先建 `.venv_asr` 环境（README 已含指引）；Omni 模型显存要求 ≥12GB
