# 本地角色挂载与情感注入综合技术方案

> 工程代号：**EmoCompanion**（Bei-offline persona 7B）
> 面向：无需训练、角色人格挂载、情感自然注入、高还原度的 7B 本地推理
> 环境：Qwen2.5-7B INT4 ｜ 8GB 显存可用（总占用 < 7GB，留 1GB 余量）｜ 3–5 token/s
> 三档对照：4GB / 8GB / 16GB
> 角色原料：`EmoCompanion工程/02_角色参数与数据/`（由 `F:\打标\数据层` 权威数据清洗而得，已做 小伴→EmoCompanion 同音归一化，源 F 盘未改动）

---

## 〇、结论速览

- **核心载体选 P3 锚点 / P5/P6 状态向量，放弃 P1 回响池作为角色人格主载体**（P1 依赖本地 hook + 大随机投影，7B 下投影矩阵即 ~933MB，违反 ≤1GB 预算；且回响池是"情境情绪"，不是"人格常量"）。
- **推理引擎选 P6 情感导演 EDD（综合 0.7046，全家族最高）**，叠加 P1.5 自动适配总开关与 P3×P4 双通道；沿用家族"情感先于表达"的解码期零权重注入，完全满足"不训练、不改权重、可热插拔"。
- **角色人格= 从打标数据提取的"情感特征谱"（低维连续状态向量 v_角色 + 角色偏移量）**，不是提示词模板；角色包 ≤10MB，热切换只需换 `v_角色/锚点行/高频词袋/抑制表`。
- **分层控制避免标签化**：人格基调（慢、稳定）× 会话潮汐（中）× 情境反应（快）三层正交叠加；拒绝"非黑即白"情绪切换。
- **6/8/10/12GB 全部可跑**；8GB 为优化基准，情感注入额外显存开销压到 <1GB（可选全部 CPU 外置情感计算，仅 `V×1` 引导张量上 GPU）。

## 一、资源盘点与家族方案评判（P1→P7 纵向价值）

基于对 `语义回响/`、`P1_5/`、`锚点回响（Anchor Echo）/`、`情感潮汐解码（ETD）/`、`KV 情感共振解码/`、`lora外挂/`、`最后版本！/` 的源码与实验报告（`P1_5/总结报告/语义回响家族P1-P4实验总结报告.md`、`KV 情感共振解码/评测结果/P6_情感导演_实验报告_2026.md`）的系统检索：

| 编号 | 方案 | 操作空间 | 核心机制 | 对 7B/8GB 本任务的价值 |
|---|---|---|---|---|
| P1 | 语义回响 SE | 表示空间 | hidden_state 钩子→回响池质心→`logits += 质心@随机投影×λ` | 情绪细腻度证明（熵+17.9%~45%）但钩子+大投影，7B 下不可选作主载体 |
| P1.5 | 通用兼容层 V2 | 配置空间 | `λ=基础(hidden_dim)×架构族×量化因子` + 思考链中断兜底 | **总开关**，4bit×0.75 关键，必留 |
| P2.5 | 情感潮汐 ETD | 概率空间 | `p′∝p^(1-α)·q_emo^α` 乘性重加权 + AI 腔三通道抑制 | 方向+密度控制、AI 腔抑制（+18%→+91% 的胜负手）、闭源 API 可跑 |
| P3 | 锚点回响 AE | 嵌入空间 | `logits += β·tanh(S·v_target/T)`，打分表 S∈R^{V×K} 静态 3.6MB、零钩子、tanh 硬上限不可坍缩 | **最佳工程载体**：零显存增量、三级降级、全词表覆盖 |
| P4 | KV 情感共振 KER | 注意力缓存 | `K[p] *= 1+κ·clip(S[token_p]·v_eff,0,1)` | 让模型"看得见"情感；P3×P4 双通道全场最高（win_rate 0.2667） |
| P5 | 超融合 UFD | 全空间 | DSA(动态自参照方向) + DMR(稠密乘性) + P1.5 参数贯穿 | 机制级融合里程碑；DMR 补 P3 稀疏词表 OOV 短板 |
| P6 | 情感导演 EDD | 导演层 | TAD/PIS/OQC 三层调度 + 5 通道 + **角色感知锚定 `v_target=0.7·v_角色+0.3·v_用户`** + 身份硬拦截 | **本方案主引擎**：综合 0.7046，多模型泛化 +67%~+233%，峰值显存与裸持平 |
| T1 | 训练态微调外挂 | 训练 | LoRA 情感微调 | **弃用**：本任务"不训练"；但 T1 结论可作为评估对照（是否有否） |

**家族共同纪律（直接复用）**：熵<0.6 或重复率攀升→注入强度减半重试，连续 3 次归零裸采样；兜底保"不坍缩"。

## 二、方案选型说明（为什么选这些、为什么放弃那些）

### 2.1 为什么放弃的候选

1. **放弃 LoRA/T1/全量微调**：违反"无需训练"硬约束；角色切换＝换 adapter 需重新加载权重，无法热切换，且微调数据不足（<100 条禁用前提）。
2. **放弃 P1 回响池作人格主载体**：① 需本地 forward hook，7B 大模型投影矩阵 ≈ 0.9GB，直接吃光情感预算；② 回响池随对话动态累积，是"当下情境情绪"，无法表达"EmoCompanion是谁"这个人格常量；③ 1.5B/7B 4bit 下质心范数 250–450 会灾难性坍缩（重复率 83–98%），需 P1.5/P2.5 压制，工程代价大于收益。→ 降级为"情感反应通道"（P6 的 DSA 内心态即其精神延续）。
3. **放弃纯提示词人设 / system-prompt 人格**：机械感强、易被"太好了！"模板劫持（文献级证据：P6 v6.5 前兄长/老师人设 fidelity 仅 0.8）。仅在 P6 已有"人设 base + 身份拦截"体系下做弱化辅助，不承载人格。
4. **放弃单一 KV 共振（P4 单通道）**：实验证明 P4 单通道在 1.5B 上不敌裸（AI 腔压制），必须与 P3 logits 通道叠加。作为子通道保留。

### 2.2 为什么选这些

| 选中组件 | 理由（对齐约束） |
|---|---|
| **P6 EDD 为引擎** | 综合 0.7046 全家族第一；零权重、跨模型（Qwen2.5/1.5B/3B、Qwen3 均 +），峰值显存与裸持平——正是"8GB 可用、尽力还原"要求的现成成熟解 |
| **P3（打分表/锚点）为人格载体接口** | 静态、零 hook、全词表、`V×K` 仅 ~3.6MB、tanh 硬上限"机制不可坍缩"；把"EmoCompanion"人格编码到模型词表坐标，天然支持热切换 |
| **P5/P6 状态向量 v_eff 为统一引导** | `v_eff = normalize((1-γ)·v_target + γ·v_dyn)`，外部 VAD 目标 × 内部 hidden 态，方向连续，是实现"连续情感流动"的载体 |
| **P1.5 为参数总开关** | 4bit×0.75、架构族因子——解决 INT4 注入敏感放大；未注册模型/兜底安全 |
| **P2.5 乘性重加权 + AI 腔抑制** | 有界几何插值数学上不可能坍缩；AI 腔抑制是"更像人"的制胜点 |
| **打标情感特征谱** | 权威原料（6951 条合格微调 + persona_traits/VAD/声学/情感标签频率），为"EmoCompanion"生成可量化情感基底 |

## 三、角色人格如何挂载（核心设计）

### 3.1 人格 ≠ 提示词：人格 = 可加/可替换的"情感状态向量"

把角色拆成一个**低维连续状态向量** + **一组词表坐标偏置**，全部解码期注入，热切换即替换：

```
角色包 (<=10MB) ═══▶ 加载进推理器
┌────────────────────────────────────────────────────────────┐
│ EmoCompanion.json (角色包 schema)                                    │
│  1. 角色状态向量  v_角色 ∈ R^K      (K≈6~32) ← 来自情感特征谱   │
│  2. 锚点行偏置    ΔS_角色[w]        (词表稀疏高置信条)          │
│  3. 人设 traits    warmth/playfulness/sassiness/energy/formality│
│  4. 高频情感词袋  (回响池头+长尾，冷启动不冷)                    │
│  5. 高低唤起抑制表 (模板劫持拦截，v6.5 经验)                     │
│  6. 身份拦截句库   ("我是EmoCompanion"暴露保护)                          │
│  7. 语言指纹       (f0/speech_rate/停顿 的"说话方式",不注入文本) │
└────────────────────────────────────────────────────────────┘
```

**三层人格正交化**（关键创新，避免"标签化"）：

| 层 | 时间尺度 | 载体 | 作用 |
|---|---|---|---|
| 人格基调层 | 慢（整场稳定） | `v_角色`、`行为偏移 ΔS_角色` | 回答"EmoCompanion是谁"：温柔/活泼/闹腾/羞怯的底色，跨轮不漂移 |
| 会话潮汐层 | 中（分钟级） | VAD 累积轨迹 + PIS 进度调度 | 回答"这场对话往哪个情绪走"：连续演变而非跳变 |
| 情境反应层 | 快（句级） | DSA 内心态 + P2.5 重加权 | 回答"这句话怎么接"：对用户内容即时共情 |

三层用 `v_eff = w1·v_角色 + w2·v_潮汐 + w3·v_内心` 在低维空间合成一次引导量，再同时驱动 P3 logits 通道与 P4 KV 通道——**一处合成、处处生效**。

### 3.2 SemanticEcho 参数集与"角色嵌入/状态向量"如何取舍

- **不直接把 SemanticEcho 回响池当"情感回响池"挂角色**：回响池是无角色标签的情境情感；直接当角色池会导致所有角色共用一个质心，无法区分"EmoCompanion vs 隔壁主播"的细微差异（1.5B 家族实验 EmoCharacter fidelity 仅在 0.88 上下，说明共性>个性）。
- **正确用法**：回响池保留为"情境情感、惊艳度"层（细腻度来源），其内容用 `ΔS_角色`(角色偏移锚点)引导到EmoCompanion的表达域；主角色的身份由 `v_角色` 状态向量承担。这样"回响池=泛情商+情境","v_角色=人格常量","模型词表坐标=EmoCompanion专属温度"三者解耦，我在上面 3.1 就叫**解耦式情感向量 + 分层控制**。

### 3.3 从打标数据提取"EmoCompanion情感特征谱"

原料（`02_角色参数与数据/微调数据/`）每条含：`persona_traits`、`valence/arousal/dominance`、`emotion_intensity`、`情感标签[]`、`f0/speech_rate/pause_ratio/energy/voice_quality`、`discrete_emotion`、`时间轴分段` 等。**提取管线**：

```
① 按角色聚（EmoCompanion/其他主播） → 只取EmoCompanion
② persona_traits 直接聚合均值 → 人格五维连续值
③ valence/arousal/dominance 的分布(均值±std) → VAD 基底
④ 情感标签 / discrete_emotion 词频 → 情感词分布(↳ 情感词袋+锚点K维投影)
⑤ 声学特征(非注入文本,记录为"说话方式"陪衬,用于多模态一致性比对)
⑥ 生成 v_角色 = 融合嵌入(小 MLP,<1M 参数,CPU 即可)：
    把 ②③④ 压成 K 维单位向量，误差为置信区间
```

产出 `EmoCompanion_情感特征谱.json`（约几 KB）→ 合并进角色包。**整套离线完成，推理期零训练、零微调。**

## 四、系统架构图（数据流 · 推理流程 · 角色交换）

```
══════════ 离线段（不打标、不训练） ══════════
F:\打标\数据层(权威) ──清洗/同音归一化──▶ 02_角色参数与数据
        │                                   │
        ▼                                   ▼
  特征谱提取 v_角色 ──────────────▶ EmoCompanion角色包.json(≤10MB)

══════════ 在线段（解码期零权重） ══════════
用户输入 ─▶ 感知层(CPU)：文本→VAD 连续态→会话潮汐轨迹 t
              └ 决策层(CPU)：目标决策器 → α(t), β(t), κ(t)  [P1.5调度]
用户内容(句级) ─▶ DSA 内心态 v_dyn          [P5 P1思想]  ┐
角色基底 v_角色 + 潮汐 v_tide + v_dyn  ──▶ v_eff(x综合) ─┴▶ 驱动两通道
                                                    ┌────────────────────────────┐
  Qwen2.5-7B INT4(常驻,4.5GB) ◀── KV cache ◀──── property: P3 logits 偏置(V×β·tanh)
  forward 每步 ─▶ logits ─▶ +P3 锚点注入 ─▶ +P2.5乘性重加权 ─▶ 采样 ─▶ 输出 token
  注意力: cache 中情感 token 的 K ←─ P4 共振调制(K×κ·clip(g,0,1))
                                                    └────────────────────────────┘
  兜底(在线): OQC─熵/重复率/角色漂移 → 强度×0.5→归零；身份硬拦截/模板劫持抑制
角色热切换: 仅替换 v_角色/ΔS_角色/情感词袋/抑制表(常驻内存指针切,无权重重载)
```

关键点：
- **GPU 上只有两处情感张量**：每步 `V×1` logits 偏置（临时）+ KV 共振的 in-place 缩放（无新增）。打分表 S、情感词袋、决策器全部 **常驻 CPU / 共享内存**，GPU 仅按步取 `V×1`。→ 情感注入"显存几乎为零"，天然 <1GB。
- **推理器直接用 llama.cpp/CTransformers 装 INT4 GGUF**（`RAG模型缓存/Qwen3-8B-Q4_K_M.gguf` 已在用同类栈），P3/P4 需要 past_key_values / logits —— 用 llama.cpp 需走 logits 回调 + KV 指针，或用 HF+bitsandbytes 4bit。**工程取舍见 §7**。

## 五、显存与速度估算（8GB 基准，Qwen2.5-7B INT4）

| 环节 | 显存占用 | 耗时/开销 | 备注 |
|---|---|---|---|
| 7B 权重 INT4(GGUF/AWQ) | ≈ 4.4–4.8 GB | 一次性加载 | 常驻 |
| KV cache（~4k ctx, GQA）| ≈ 0.5–1.0 GB | 随上下文增长 | 8GB 下建议 2–4k 上下文 |
| P3 打分表 S(V×K) | 0 (CPU) | 生成期 1 次矩阵乘 ~3.6MB | 预计算 |
| P3/P4 每步偏置 | V×1 fp32 ≈ 0.6MB GPU | <0.2ms | 热张量，随取随丢 |
| 情感向量/决策器(v_角色/MLP) | 0 (CPU) | <1ms/step | NLP 小模型 |
| 在线兜底扫描 | 0 | <0.3ms | OQC |
| **合计** | **≈ 5.2–5.9 GB** | — | **≥1GB 余量达标(<7GB)** |

速度：7B INT4 在 RTX3080 走 llama.cpp 约 14–20 tok/s（家族 P1.5 已测 1.5B 21.3 tok/s，7B 按尺度折算）；注入开销 <7%（P6 实测 19.7 vs 裸 20.1）→ **预计 12–18 tok/s，远超 3–5 最低目标**。CPU offload 情感计算后 GPU 仅剩矩阵采样，速度几乎无损。

## 七、8GB 约束下的三点硬优化

1. **量化策略**：INT4 必选；P1.5 量化因子×0.75 抑制注入敏感放大。INT4 影响的主要是 logits 精度，而情感注入主力在**嵌入/注意力空间**（P3/P4），该空间精度损失远小于 logits，故情感表达能力受影响有限。个别最弱 token 可对 P3 通道提到 fp16 重打分（仅边标）。
2. **情感向量全 CPU**：VAD 感知、目标决策器、DSA、v_eff 合成全在 CPU/共享内存，GPU 仅收 `V×1`。→ 显存零贡献、GPU 利用率让位给生成。
3. **打分表/KV 分档**：P3 表常驻无争议；P4 仅对"情感 token"（`g(p)>0` 的子集）做 in-place 缩放，不复制整段 cache，避免额外显存翻倍。

> 引擎选型（工程化）：8GB 建议 **HF(bitsandbytes 4bit) 拿 logits + past_key_values** 直接复用家族 P3/P4/P6 源码；若追求吞吐，用 **llama.cpp + logits 回调 + KV 指针**，需将 P3/P4 适配为回调钩子（一次性改造）。两者都零训练。

## 八、改进路线（在现有方案基础上）

- **α–β–κ 联合自适应**：突破 P1.5 的独立因子，改为感知"会话潮汐+角色基底+输入复杂度"协同调度的轻量强化/查表（仍零训练），进一步提升 7B 大模型平稳性。
- **角色级 KV cache 预设**：为EmoCompanion预置少量"角色记忆 token"到 cache（对应"我是EmoCompanion"表达域），人设不止影响概率还参与注意力，解决冷启动无角色锚。
- **多角色并发**：`v_角色`叠加（如"EmoCompanion×温柔表妹"），用角色包线性组合实现个性混合，拓展到性别/年龄连续轴。
- **声学指纹闭环**：目前 f0/语速只做陪衬；后续接入 TTS 时让"说话方式"反推 VAD 目标，做到文↔声同一情感（多模态一致性）。
- **对抗式评估**：用云端 72B 生成"EmoCompanion对抗样本"（诱导角色漂移/戳穿身份），反哺 OQC 抑制表与身份拦截库，形成"还原度-防伪装"双指标。
- **社区化角色包**：抽象 `角色包 schema`（v0.1），支持第三方数据→特征谱→角色包的开源流水线，让"打标→角色"成本降到分钟级。

## 十、实测修正与落地校准（2026-08 本地实跑）

> 依据 `05_三档显存测试/实测报告.md`、`8GB正式评估报告.md`（8 模型 × 多β × 人设/无人设 × LLM-Judge 去偏置）。

- **人格还原的主体是谁**：实证表明在 **instruct 模型 + 允许极轻人设提示** 下，基线即可把EmoCompanion裁判保真拉到 86–92。→ **人设提示段承担"人格骨架"，解码期注入承担"细腻度/防复读/防塌缩"**，二者分层而非互斥。这与方案第三章"人格= 状态向量非模板"的主张需并轨：**建议"人设提示(骨架) + v_角色情感方向(细粒度牵引)"双轨**，热切换角色包内含两者。
- **P3 注入的真实收益边界**：在 chat 真角色扮演设置下，LLM-Judge 赢率≈机会水平（含无人设对照）；可测收益 = 多样性↑、2-gram 重复率↓、跨规模不塌缩。其"精准情感注入"优势体现在**需覆盖模型既有倾向 / 弱提示 / base 补强**的场景，不作"更还原人格"的虚报。
- **参数校准**：P3 β 推荐 0.6–1.0（7B@1.4 保真回退至 79 需避开）；4bit × 0.75 保留；Qwen 系直接适用、gemma 类需架构因子下探（见实测）。
- **三档映射实测**：4B：稳态 4.5G（8GB 档 ✅）；7B：稳态 8.3G（8GB 档偏紧，建议降上下文，或主推 4B、7B 归 10–12G）；8B：10.6G（16G 档）。情感注入本身显存近零，大头是模型权重+KV。
- **达标验收线已固化**：`formal_eval.py`（LLM-Judge 随机 A/B 去偏置 + 0–100 缘分保真度）作为"还原度达标"的可复现裁判线。
