# 第二十六章 端到端实战：从零搭一个"带记忆"的 AI 助手

前面 25 章把理论和单项技能都讲完了，这一章把它们**串成完整项目**。我们从零到一，搭建一个"有角色、有记忆、能翻知识库"的 RWKV 陪伴助手。你跟着敲，最后会得到一个真正能跑起来的小产品。

## 26.1 项目目标与整体架构

我们要做的项目叫 **"Memo 伙伴"**：一个带长期记忆的 AI 聊天助手。核心需求三条：

1. **有角色**：设定成一个"温柔的倾听型朋友"；
2. **有记忆**：重启程序后还记得你是谁、聊过什么；
3. **有知识**：能查一份本地知识库再回答（RAG）。

整体架构非常轻——不需要大集群，一台电脑就能跑：

![Memo 伙伴项目架构](img/fig30_memo_arch.png)

| 模块 | 技术 | 作用 |
| --- | --- | --- |
| 前端 | 原生 HTML + JS | 聊天界面 |
| 后端 | Python + FastAPI | 接收请求、编排逻辑 |
| 推理 | RWKV（rwkv pip 库） | 生成回复 |
| 记忆 | SQLite（存状态文件） | 跨会话持久化记忆 |
| 知识库 | 简单向量检索（可选） | RAG 外挂资料 |

**关键点**：RWKV 的"状态文件"在这里就是记忆的物理载体——我们把状态存进数据库，用户回来时读出来接着用，这就是它相对 Transformer 的工程红利。

## 26.3 第一步：加载模型与基础对话

写一个最基础的 `llm.py`，把模型封装成"说一句话 → 返回回复"的接口：

```python
# llm.py —— RWKV 推理封装
from rwkv.model import RWKV
from rwkv.utils import PIPELINE

MODEL_PATH = "./models/rwkv-7/rwkv-7.pth"
VOCAB_PATH = "./models/rwkv-7/rwkv_vocab_v20230424.txt"

# strategy: "cuda fp16" 用显卡；"cpu fp32" 没显卡也能跑
model = RWKV(model=MODEL_PATH, strategy="cuda fp16 * -> cuda fp16")
pipe = PIPELINE(model, VOCAB_PATH)

def generate(prompt: str, state=None, temperature=0.8):
    """返回 (回复文本, 新状态)"""
    # RWKV 官方库：把整段 prompt 一次性灌入，得到输出和最终状态
    out, state = model.run([prompt], state)
    return out, state

if __name__ == "__main__":
    text, st = generate("你好，我是谁？")
    print("助手:", text)
```

> 注意：官方 `rwkv` 库的 `model.run` 输入通常是"token 序列"。不同版本 API 略有差异，请以你安装版本的 README 为准；核心逻辑不变——**每次调用都传回上一次的 state，实现连续记忆**。

## 26.4 第二步：角色设定（System Prompt）

角色不是一个"开关"，而是写进每一轮输入开头的"身份卡"。我们把角色设定做成可配置：

```python
# prompt.py —— 角色与对话模板
ROLE_CARD = """你叫 Memo，是一个温柔、耐心的倾听型 AI 朋友。
你说话简短、口语化，经常关心对方的感受。
如果对方提到难过的事，先共情，再给建议。
你永远使用简体中文回复。"""

def build_prompt(user_input: str, history: list[str]) -> str:
    """history 是最近几轮的短记忆，状态文件管长记忆"""
    chat = "\n".join(history[-6:])          # 只保留最近 6 条，防爆 token
    return f"{ROLE_CARD}\n\n最近的对话：\n{chat}\n用户：{user_input}\nMemo："
```

**为什么这样设计**：RWKV 的"状态"负责**长期记忆**（跨会话、记大事）；显式塞进 prompt 的 history 负责**短期上下文**（让回复更连贯）。两者分工，这是 RWKV 应用最舒服的用法。

## 26.5 第三步：把记忆做成"数据库"

这是本项目最 RWKV 的部分——**状态即记忆，存进数据库**：

```python
# memory.py —— 用 SQLite 存状态，实现跨会话记忆
import sqlite3, pickle

DB = "memo.db"

def _conn():
    c = sqlite3.connect(DB)
    c.execute("CREATE TABLE IF NOT EXISTS sessions "
              "(uid TEXT PRIMARY KEY, state BLOB, history TEXT)")
    return c

def save_session(uid: str, state, history: list[str]):
    c = _conn()
    c.execute("INSERT OR REPLACE INTO sessions VALUES (?,?,?)",
              (uid, pickle.dumps(state), "\n".join(history)))
    c.commit(); c.close()

def load_session(uid: str):
    c = _conn()
    row = c.execute("SELECT state, history FROM sessions WHERE uid=?", (uid,)).fetchone()
    c.close()
    if not row:
        return None, []
    return pickle.loads(row[0]), row[1].split("\n")
```

**工作原理**：用户每说一句话，我们拿到新的 `state`，立刻存库。下次用户再来，直接读回 `state`——RWKV 就"还记得"之前的所有对话。整个过程不需要存任何原始长文本，一个状态文件搞定。

## 26.6 第四步：接入 FastAPI，做成 Web 服务

```python
# app.py —— FastAPI 聊天接口
from fastapi import FastAPI
from pydantic import BaseModel
from llm import generate
from prompt import build_prompt
from memory import load_session, save_session

app = FastAPI()

class ChatIn(BaseModel):
    uid: str
    text: str

@app.post("/chat")
def chat(body: ChatIn):
    state, history = load_session(body.uid)          # 1. 读回记忆
    prompt = build_prompt(body.text, history)        # 2. 组 prompt
    reply, new_state = generate(prompt, state)       # 3. 生成回复
    save_session(body.uid, new_state, history + [body.text, reply])  # 4. 存记忆
    return {"reply": reply}

# 启动：uvicorn app:app --port 8000
```

```html
const UID = "user-001";          // 同一 UID = 同一份记忆
async function send() {
  const inp = document.getElementById("inp");
  const box = document.getElementById("box");
  const text = inp.value; if (!text) return; inp.value = "";
  box.innerHTML += `<div class="me">${text}</div>`;
  const res = await fetch("/chat", {
    method: "POST",
    headers: {"Content-Type": "application/json"},
    body: JSON.stringify({uid: UID, text}),
  });
  const data = await res.json();
  box.innerHTML += `<div class="ai">${data.reply}</div>`;
  box.scrollTop = box.scrollHeight;
}
</script>
</body>
</html>
```

启动后在浏览器打开 `http://localhost:8000/index.html`，就能和"带记忆的 Memo"聊天了。

## 26.8 第六步（可选）：接入本地知识库（RAG）

想让 Memo 能回答你资料里的问题？给它加一个"外挂知识库"：

```python
# rag.py —— 极简 RAG：关键词 + 向量混合检索
# 这里用最朴素的实现演示思想；生产可换 FAISS / Chroma / Milvus
import hashlib, sqlite3

def add_doc(text: str):
    """把一段资料按句切分后入库"""
    for sentence in text.replace("\n", "。").split("。"):
        if len(sentence.strip()) > 10:
            conn = sqlite3.connect("kb.db")
            conn.execute("CREATE TABLE IF NOT EXISTS docs "
                         "(id TEXT PRIMARY KEY, content TEXT)")
            h = hashlib.md5(sentence.encode()).hexdigest()
            conn.execute("INSERT OR REPLACE INTO docs VALUES (?,?)", (h, sentence))
            conn.commit(); conn.close()

def search(query: str, topk: int = 3) -> str:
    """按关键词命中程度检索最相关的句子"""
    conn = sqlite3.connect("kb.db")
    rows = conn.execute("SELECT content FROM docs").fetchall()
    conn.close()
    q = set(query)
    scored = sorted(rows, key=lambda r: -len(q & set(r[0])))
    return "\n".join(c for c, *_ in scored[:topk])
```

然后改一下 `build_prompt`，把检索结果作为"参考资料"喂给模型：

```python
def build_prompt(user_input, history):
    ref = search(user_input)          # 知识库检索结果
    return (f"{ROLE_CARD}\n\n参考资料：\n{ref}\n"
            f"（资料若无用请忽略）\n\n最近的对话：\n{history[-6:]}\n"
            f"用户：{user_input}\nMemo：")
```

**效果**：现在 Memo 既能"记住你"（状态），又能"查资料"（RAG），还"有人设"（角色卡）。一个三合一的小助手就完成了。

**常见的三个坑及解法：**

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| 状态序列化失败 | 重启后记忆丢失 | 确认用 `pickle` 且版本一致；或改存为 JSON 数组格式 |
| 显存不足 | 启动报 CUDA OOM | 换 `strategy="cuda fp16"` 或下载 Q4 量化版 |
| 回复重复/复读机 | 一直说同样的话 | 调高 `temperature`、打开重复惩罚 |
