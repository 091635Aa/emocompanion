# 第五章 架构拆解：RWKV 内部长什么样

这一章我们钻进 RWKV 的内部，把它的"零件"一个个拆开看。别怕，我们会一直用"记忆"和"笔记"的比喻，公式只是顺便提一下。

## 5.1 整体结构：堆叠的残差块

RWKV 的整体骨架和 Transformer 很像：**输入被切成 token → 向量化 → 经过 N 层相同的"块（block）"堆叠 → 输出预测。** 每一层块都由两个子块组成：

1. **Time Mixing（时间混合）**：负责"在时间轴上混合信息"，相当于注意力层的角色，是 RWKV 的记忆核心。
2. **Channel Mixing（通道混合）**：负责"在每个位置上做特征加工"，相当于前馈网络（FFN）的角色。

![RWKV 残差块结构](img/fig08_rwkv_block.png)

从上图可以看到，两个子块之间都有**残差连接（Residual）+ LayerNorm**，和 Transformer 的"残差 + 归一化"套路一致。**残差连接的意义**：让信息能"抄近路"绕过复杂模块，既帮助训练稳定，也让深层网络可训练。

## 5.2 第一个零件：Token Shift（词元转移 / 短卷积）

这是 RWKV 的一个小但关键的技巧。**在每个子块计算前，它会把"上一个时刻的输入"和"当前时刻的输入"按比例混合一下。**

![Token Shift 示意图](img/fig09_token_shift.png)

数学上就是线性插值：

```text
Shift(x[t]) = μ · x[t] + (1 - μ) · x[t-1]
```

其中 μ 是混合系数（不同通道可以不同）。直观地说，它让每个位置"自带一点上一时刻的影子"，从而让模型在计算时能"摸到"邻近的历史信息。

- **小白版**：相当于每次动笔前，先瞥一眼自己刚写的上一句话，让上下文更连贯。
- **为什么叫"短卷积"**：它等价于一个核长度只有 2 的卷积，计算量几乎为零，却显著提升了性能。
- **进阶版**：在 RWKV-5/6 中，Token Shift 升级为"数据相关"的版本，让模型按内容决定混合比例。

## 5.3 第二个零件：Time Mixing / WKV 算子（记忆核心）

这是 RWKV 最重要的发明，用"**WKV 算子**"替代了注意力。它的流程可以拆成三步：

![WKV 计算流程](img/fig10_wkv_flow.png)

1. **写入**：当前词的 K（键）和 V（值）被写进"记忆状态 S"；
2. **衰减**：旧的记忆按"W（可学习的衰减系数）"指数级淡忘——越早的信息权重越低；
3. **读出**：用 R（感受态，类似查询）从记忆里加权读出信息，再经过门控得到输出。

用公式表达（RWKV-4 的经典形式）：

```text
WKV 核心：output_t = R_t · ( Σ_{i<t}  exp(-w·(t-i)) · (K_i · V_i) + exp(u)·(K_t·V_t) ) / 分母
```

- `exp(-w·(t-i))` 就是**按时间距离打折**：离得越远，权重越小（但不会完全消失）。
- 中间那个 `u` 是"当前时刻的额外权重"（因为当前信息通常最重要）。
- R_t 决定"这条信息要不要影响我"。

**为什么这样能代替注意力？** 注意力是"每个词和所有历史词两两打分"；而 WKV 把历史**预先压缩进一个固定大小的状态 S**，读的时候不再逐个比对，而是"一把抓出来再按新旧打折"。前者精确但贵，后者省但略微"糊"。

> 公式中的"分母"用于归一化，避免状态不断累加而爆炸。RWKV-4 用一个单独的状态保存归一化因子；RWKV-7 改进了归一化方式，这里不展开。

## 5.4 第三个零件：Channel Mixing（通道混合）

如果说 Time Mixing 管"时间"，那 Channel Mixing 就管"特征"。它在**同一个时刻上**，对词向量的各个维度（通道）做非线性加工，作用类似 Transformer 的前馈网络 FFN。

它同样用 R、K、V 结构，但"混合"发生在通道之间而非时间之间：

```text
Channel Mixing：out = sigmoid(R) ⊙ ( W2 · gelu(W1 · K) ⊙ V )
```

- 先用 `gelu` 做非线性变换；
- 再用 R（感受态）做门控，决定"这些特征要不要被激活"；
- 作用和 FFN 一样：**提升模型的表达能力**（把特征空间映射到更高维再压回来）。

## 5.5 它为什么"无注意力也能行"：三件套合力

把上面的零件拼起来，你就明白 RWKV 的记忆逻辑了：

![无注意力也能行的三件套](img/fig24_why_works.png)

| 机制 | 角色 | 负责的记忆类型 |
| --- | --- | --- |
| Token Shift | 短程记忆 | 刚看到的邻近词 |
| 指数衰减状态（WKV） | 长程记忆 | 整段历史的压缩摘要 |
| R 感受态门控 | 选择性注意 | 决定"要不要理会某条信息" |

三个机制合起来，用一份**固定大小的状态**装下整个上下文，需要哪段按权重调出来——这就是它没有注意力却"记得住"的原因。

## 5.6 与 Transformer 逐层"翻译"对照

为了方便学过 Transformer 的人理解，我们做一张"翻译表"：

| Transformer | RWKV 对应物 | 说明 |
| --- | --- | --- |
| 自注意力（Self-Attention） | Time Mixing（WKV） | 都做"序列信息聚合" |
| Q/K/V | R（感受态）+ K + V | 角色类似，机制不同 |
| 位置编码（Positional） | W 衰减 + Token Shift | 用"时间衰减"隐含位置信息 |
| 前馈网络 FFN | Channel Mixing | 都做逐位置非线性变换 |
| 残差 + LayerNorm | 残差 + LayerNorm | 几乎一样 |
| KV Cache（推理） | 隐藏状态 S | 一个是"完整历史"，一个是"压缩摘要" |

**核心差异浓缩成一句话**：Transformer 靠"保存所有历史 + 两两比对"来记忆；RWKV 靠"压缩成一份状态 + 按新旧打折"来记忆。

## 5.7 双模式背后的数学视角

为什么"同一套权重"既能并行训练又能循环推理？关键在 WKV 的可分解性：

- **推理（循环形式）**：状态按步更新 `S_t = f(S_{t-1}, x_t)`，每步只依赖上一步 → 天然串行、固定内存。
- **训练（并行形式）**：因为衰减系数 `w` 与输入无关（RWKV-4 及以前），整条时间轴上的 WKV 可以写成"前缀和"（cumulative sum），一次性并行算出所有位置的输出 → GPU 全开。

RWKV-6/7 引入了"数据相关"的衰减和更复杂的更新，并行不再那么简单，官方用专门的 CUDA 内核（WKV kernel）来高效实现——这也是为什么用 RWKV 时通常建议开启官方内核加速（第九章会讲）。
