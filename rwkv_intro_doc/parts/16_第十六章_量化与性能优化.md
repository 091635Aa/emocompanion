# 第十六章 量化与性能优化：把 RWKV 压榨到极限

RWKV 已经很"省"了，但还能更省。这一章讲清楚**量化**是什么、怎么选，以及各种**提速/省内存**的实用技巧，让你在有限的硬件上发挥 RWKV 的最大威力。

## 16.1 什么是量化：用更小的数存模型

模型权重默认用 32 位浮点数（FP32）或 16 位（FP16）存储，占用空间大。**量化**就是把这些"大数"用更小的精度表示，从而显著减少内存、加快速度。

| 精度 | 每参数比特 | 7B 模型体积（约） | 效果 |
| --- | --- | --- | --- |
| FP32 | 32 bit | 28 GB | 最准，最贵 |
| FP16 | 16 bit | 14 GB | 精度无损，常用 |
| INT8（Q8_0） | 8 bit | 7 GB | 精度损失小，强烈推荐 |
| INT4（Q4_K_M 等） | 4 bit | 4 GB | 更省，质量略降 |
| NF4 / Q3 | 3-4 bit | 3 GB | 极致省，质量下降明显 |

> **RWKV 的量化建议**：社区实测推荐 `FP16` 或 `Q8_0` 档。更低的 Q5/Q4 虽能大幅省内存，但会明显降低回复质量——"够用"和"好用"之间要权衡。

## 16.2 常见量化格式与工具

| 格式 | 说明 | 适用 |
| --- | --- | --- |
| GGUF | llama.cpp 生态的量化格式 | llama.cpp / Ollama |
| GPTQ | 面向 GPU 的量化 | vLLM 等 GPU 推理 |
| AWQ | 面向 GPU 的量化 | 激活感知量化 |
| fp16i8 | RWKV Pip 的混合精度 | 官方推理 |

## 16.3 推理提速技巧（按性价比排序）

### 16.3.1 技巧一：开启官方 WKV 内核

这是**最重要的一条**。RWKV-6/7 的数据相关衰减需要专用 CUDA/ROCm 内核才能高效并行：

- 用 RWKV Pip：NVIDIA 显卡选 `cuda fp16`，显存不足用 `cuda fp16i8`；
- 用 RWKV-Runner：RWKV-7 + CUDA 可切 **Albatross** 内核做性能对比；
- 用 vLLM：自动启用优化内核。

> 很多"RWKV 很慢"的反馈，都是因为没开官方内核、在 CPU 上裸跑导致的。

### 16.3.2 技巧二：选对模型规模

| 硬件 | 推荐模型 |
| --- | --- |
| 4GB 内存 | RWKV-7 1.5B（Q8） |
| 8GB 内存 | RWKV-7 2.9B（Q8） |
| 8GB 显存 | RWKV-7 2.9B fp16 / 7B 量化 |
| 24GB 显存 | 7B fp16 / 14B 量化 |

**先小后大**：先用跑得动的最小模型验证，再逐步升级。

### 16.3.3 技巧三：控制上下文长度

虽然 RWKV 长上下文"免费"，但过长会消耗更多预填充时间。按需设置：

```bash
# Ollama
/set num_ctx 8192

# llama-server
./llama-server -m model.gguf --ctx-size 8192

# vLLM
--max-model-len 8192
```

### 16.3.4 技巧四：利用流式输出提升体验

生成是逐 token 的，流式输出（Streaming）让用户**边生成边看**，体感速度快很多（见第十章）。

### 16.3.5 技巧五：批量推理 / 服务化

生产场景用 vLLM 的 **continuous batching（连续批处理）**，把多个请求拼在一起算，GPU 利用率大幅提升，吞吐翻数倍。

## 16.4 省内存技巧（低配设备）

| 技巧 | 做法 | 效果 |
| --- | --- | --- |
| 量化模型 | 用 Q8/Q5 GGUF | 体积减半以上 |
| 关闭思考模式 | 用 `thinkdisabled` 版本模型 | 更快、省内存 |
| 限制上下文 | 调小 num_ctx | 减少状态开销 |
| CPU 多线程 | llama.cpp 设置 `-t` 线程数 | CPU 更快 |
| 内存回收 | 关闭其他占用内存的程序 | 给模型更多空间 |

```bash
# llama.cpp 用多线程跑
./llama-cli -m model.Q8_0.gguf -t 8 -c 4096

# Ollama 设置 CPU 线程
OLLAMA_NUM_PARALLEL=1 ollama serve
```

## 16.6 压测与监控：怎么确认优化有效

```bash
# 1. 监控显存/内存
nvidia-smi -l 1          # GPU 显存实时
free -h                  # 内存

# 2. llama.cpp 自带压测
./llama-bench -m model.gguf -p 512 -n 128

# 3. 简单计时
time curl http://localhost:11434/api/chat -d '{...}'
```

**需要关注三个指标**：

1. **首 token 延迟（TTFT）**：问完到开始回答的时间；
2. **生成速度（tok/s）**：每秒生成多少 token；
3. **显存/内存峰值**：是否恒定、是否够用。

## 16.7 常见性能问题速查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 生成很慢 | 没开官方内核 / CPU 跑大模型 | 开内核、换小模型 |
| 显存不足 | 模型太大或上下文太长 | 量化、调小 ctx、换小模型 |
| 首次回答特别久 | 长上下文预填充 | 缩短输入、分段 |
| 多用户一慢全慢 | 没做批量 | 用 vLLM continuous batching |
| 输出质量下降 | 量化档太低 | 用 Q8_0 / FP16 |

<div class="tip">

**本章小结**：性能优化的核心排序——① 开官方 WKV 内核（最重要）→ ② 选对模型规模 → ③ 控制上下文 → ④ 流式输出 → ⑤ 服务化批量。省内存靠量化（推荐 Q8_0）+ 关思考模式 + 限制上下文。优化前先量好"TTFT / tok/s / 内存峰值"三个指标，再针对性调优。
