# 第十五章 它是怎么被训练出来的：训练原理与实战

"部署 + 使用"讲完了，这一章回答一个更底层的问题：**RWKV 是怎么被训练出来的？** 理解了训练原理，你就明白为什么"双模式"如此巧妙，也知道了以后想自己训练/微调时该做什么。

## 15.1 训练的目标：预测下一个词

大语言模型的训练目标朴素得惊人：**给定前面的文字，预测下一个词。** 这叫"自监督学习"——不需要人工标注，互联网上的海量文本本身就是"答案"。

- 给模型看"今天天气真"，让它预测下一个词"好"；
- 看"我喜欢吃"，预测"苹果/火锅/香蕉……"；
- 看完几万亿 token 之后，模型就"内化"了语言规律和大量世界知识。

这个任务叫 **next-token prediction（下一个词预测）**，是所有 GPT 系模型（包括 RWKV）的基础。

## 15.2 双模式是怎么在训练中工作的

回忆第五章：RWKV 同一套权重有"GPT 模式（并行）"和"RNN 模式（循环）"两种跑法。**训练时用 GPT 模式，推理时用 RNN 模式**：

![双模式：训练并行 / 推理循环](img/fig11_dual_mode.png)

| | 训练（GPT 模式） | 推理（RNN 模式） |
| --- | --- | --- |
| 处理方式 | 整段序列一次摊开并行算 | 一个 token 一个 token 串行走 |
| 计算对象 | 一次算出所有位置的输出 | 每步只算当前 token 的输出 |
| 状态处理 | 用"前缀和"技巧一次性模拟 | 显式维护一个状态 S |
| 为什么能 | WKV 可分解（衰减与输入无关时可并行） | 状态式 RNN 天然支持 |

**核心洞察**：训练时的"并行"不需要真的一个个更新状态——因为 WKV 的衰减结构可以写成前缀和（cumulative sum），整条时间轴一次性并行算出。这就是"RNN 居然能并行训练"的秘密。

## 15.3 损失函数与反向传播

训练时，模型每个位置都会输出一个预测分布，我们要让它和"真实的下一个词"尽量一致：

- 用**交叉熵损失（cross-entropy）**衡量"预测得有多不准"；
- 误差通过**反向传播（backpropagation）**更新模型参数；
- 训练数据按 **batch（一批一批）** 喂给模型，用 **梯度下降** 逐步优化。

> **小白版**：模型猜错了 → 告诉它"正确答案是啥" → 它调整自己的参数，下次更接近 → 反复几万亿次，就变聪明了。

## 15.4 RWKV 训练的三个特点

### 15.4.1 特点一：训练显存更低

Transformer 训练时要保存大量中间激活（每层、每个 token 的注意力分数等）用于反向传播；RWKV 因为状态式结构，中间量更少，**训练/微调的显存占用明显更低**。这让你"单卡微调"成为可能。

### 15.4.2 特点二：天然适合长序列训练

长序列训练对 Transformer 是噩梦（显存随长度平方涨，需要各种分片技巧）；RWKV 是线性，**训练长上下文更省**。

### 15.4.3 特点三：需要专用内核加速

v6/v7 引入了"数据相关衰减"后，WKV 不能再简单写成前缀和，并行实现变复杂。官方提供**专用 CUDA 内核（WKV kernel）**高效实现，训练和推理都应尽量开启。

```bash
# RWKV-LM 训练脚本里，用 --cuda_on 或 strategy 开启官方内核
# 例如用 RWKV-LM 的 train.py：
# python train.py --load_model ... --wandb ... --ctx_len 4096 ...
```

## 15.5 训练的三个阶段

| 阶段 | 做什么 | 数据 | 目的 |
| --- | --- | --- | --- |
| 预训练（Pretrain） | 从零学语言规律和世界知识 | 海量网页/书籍（万亿 token） | 让模型"会说话、懂知识" |
| 指令微调（SFT） | 学会"听指令回答问题" | 人工编写的问答数据 | 让模型"能对话、会干活" |
| 对齐（RLHF 等） | 让回答更符合人类偏好 | 人类反馈打分 | 让模型"更友善、更有用" |

RWKV 的开源模型（如 RWKV-6 World、RWKV-7 G1）都已完成了这三个阶段，开箱即用。我们自己动手时，通常做的是**指令微调**或**State Tuning**（见第十一章）。

## 15.6 从零训练 vs 微调：成本和选择

| 方式 | 数据量 | 算力 | 时间成本 | 适合谁 |
| --- | --- | --- | --- | --- |
| 从零预训练 | 万亿级 token | 大量 GPU 集群 | 极高 | 大厂/研究机构 |
| 继续预训练 | 百亿级 token | 多卡 | 高 | 特定领域（医疗/法律） |
| 全参微调 | 百万级 | 单卡/多卡 | 中 | 有数据的团队 |
| LoRA 微调 | 万级 | 单卡 | 低 | 大多数开发者 |
| State Tuning | 千级 | 单卡 | 极低 | 个性化/人设 |

**对绝大多数人**：不要从零训练，用开源的 RWKV + 轻量微调/State Tuning 就够了。

## 15.7 一个迷你训练示例（示意）

以 RWKV-LM 仓库的训练脚本为例，理解训练入口大概长什么样（不必真跑）：

```bash
# 克隆官方训练库
git clone https://github.com/BlinkDL/RWKV-LM
cd RWKV-LM/RWKV-v7

# 单卡微调示意（具体参数以官方 README 为准）
python train.py \
  --load_model path/to/base.pth \
  --wandb off \
  --data_file path/to/my_data.txt \
  --ctx_len 1024 \
  --micro_bsz 4 \
  --epoch_steps 100 \
  --lr_init 1e-5 \
  --accumulate_grad_batches 4
```

要点：

- `--load_model`：加载基底模型（续训）；
- `--data_file`：你的训练数据（纯文本即可做继续预训练；做指令微调通常用 JSONL）；
- `--ctx_len`：序列长度；
- `--lr_init`：学习率（微调要调小，如 1e-5，避免破坏原模型）；
- 显存不足就调小 `micro_bsz` 或 `ctx_len`。

> 更友好的微调路径：用 **RWKV-PEFT**（支持 LoRA 与 State Tuning，脚本开箱即用），或直接用我们第十一章的方法。

## 15.8 训练数据：质量比数量更重要

无论预训练还是微调，数据质量都决定效果：

| 原则 | 说明 |
| --- | --- |
| 去重去噪 | 去掉重复、乱码、低质内容 |
| 多样 | 覆盖各种领域、风格、语言 |
| 干净格式 | 统一换行、编码（UTF-8） |
| 任务对齐 | 微调数据要和"上线场景"一致 |

**黄金法则**：与其堆 100 万条低质数据，不如用 1 万条高质量、贴合场景的数据。
