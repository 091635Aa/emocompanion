# 第六章 和 Transformer 到底差在哪：全面对比

这一章我们做一次"体检式"对比，把 RWKV 和 Transformer 从机制、复杂度、显存、训练、推理、效果、生态等各个维度掰开揉碎比较一遍。读完这一章，你对"什么时候选 RWKV、什么时候选 Transformer"会有一个清晰的判断。

## 6.1 一句话总结差异

先给你一个"总纲"，后面的所有细节都是它的展开：

> **Transformer：记忆靠"保存全部历史 + 两两比对"，精确但昂贵（O(N²)）。**
> **RWKV：记忆靠"压缩成一份固定状态 + 按新旧打折"，便宜（O(N)）但略"糊"。**

- Transformer 像"图书馆"，每一本书（每个 token 的 K/V）都原样保留，查资料时逐本翻阅，越大的图书馆越贵。
- RWKV 像"读书笔记"，把读过的内容浓缩成固定厚度的笔记本，随时翻、越翻越薄的成本，但记的是"摘要"而不是"原文"。

## 6.2 机制层面的对比：注意力 vs 状态

### 6.2.1 信息聚合方式

**Transformer（自注意力）**：

1. 每个词生成 Q（查询）、K（键）、V（值）三个向量；
2. 每个词用 Q 与"序列里所有词的 K"逐一打分（点积），得到 N 个注意力分数；
3. softmax 归一化成权重；
4. 用权重对 N 个 V 做加权求和，得到该词的输出。

这个过程对"序列内任意两个词"都做了一遍配对，所以叫"全对全（all-to-all）"。它的好处是**任意距离都能直接关联**（远亲也能翻到），坏处是**计算量和内存随 N 平方增长**。

**RWKV（WKV 线性注意力）**：

1. 每个词用 K、V 把信息"写进"一个固定大小的记忆状态 S；
2. 旧记忆按可学习的衰减系数 W **指数级淡忘**；
3. 每个词用 R（感受态，类似 Q）从状态 S 中"读出"信息，再经门控输出。

它不需要两两配对，只维护一份状态，所以计算量是 **O(N)**、内存是 **O(1)**。

### 6.2.2 记忆的"精确度"差异

这是两者最本质的取舍：

| 维度 | Transformer | RWKV |
| --- | --- | --- |
| 记忆载体 | 全部历史 token 的 K/V（KV Cache） | 固定大小的隐藏状态 S |
| 能否精确"翻旧账" | 能，任意位置的原文都能精确加权 | 不能，只保存压缩后的摘要 |
| 长文本信息密度 | 越高（原文都在） | 受状态容量限制 |
| 检索方式 | 逐个 token 两两打分 | 从状态中一次读出 + 衰减加权 |
| 类比 | 完整录音 / 完整账本 | 会议纪要 / 流水摘要 |

**一个重要的事实**：Transformer 的"精确回忆"在长上下文里是优势，但代价是"贵"。RWKV 用"摘要"换来了"便宜"，在大多数实际任务里，摘要已经够用；只有少数需要"逐字精确引用原文"的任务（比如某些法律文书检索），Transformer 仍占优。

## 6.3 复杂度对比：O(N²) vs O(N)

### 6.3.1 为什么 Transformer 是 O(N²)

自注意力要算一个 **N×N 的注意力矩阵**：N 个词，每个词要和 N 个词打分。所以：

- 序列长度 N=1K → 需要约 100 万次配对；
- N=4K → 约 1600 万次；
- N=32K → 约 10 亿次。

长度翻倍，计算量变 4 倍（平方）；长度翻 4 倍，计算量变 16 倍。

### 6.3.2 为什么 RWKV 是 O(N)

RWKV 的 WKV 算子每来一个 token，只做一次"固定大小的状态更新 + 一次读出"，和"之前有多少词"无关。所以：

- N=1K → 约 1K 次操作；
- N=32K → 约 32K 次操作。

长度翻倍，计算量约翻倍（线性），这才是"长上下文不心疼"的根本原因。

### 6.3.3 数字对照表（示意）

| 上下文长度 | Transformer 相对成本 | RWKV 相对成本 | 差距 |
| --- | --- | --- | --- |
| 1K | 1 | 1 | 持平 |
| 4K | 16 | 4 | 约 4 倍 |
| 16K | 256 | 16 | 约 16 倍 |
| 64K | 4096 | 64 | 约 64 倍 |
| 256K | 65536 | 256 | 约 256 倍 |

> 注意：这是"注意力部分"的理论复杂度对比，实际推理中 Transformer 有 FlashAttention 等优化、RWKV 有专用 CUDA 内核，比例会有所变化，但"随长度增长的趋势"不变——**长度越长，RWKV 的性价比优势越大**。

## 6.4 推理资源对比：KV Cache vs 隐藏状态

### 6.4.1 KV Cache 是什么

Transformer 推理时，为避免重复计算历史，会把每个已处理 token 的 K、V 向量缓存下来，这就是 **KV Cache**。它的大小随序列长度线性增长：上下文 4K 的 7B 模型，KV Cache 可能占数 GB 显存；64K 时就非常可观。

### 6.4.2 RWKV 为什么没有 KV Cache

RWKV 推理时只保留一份**固定大小的隐藏状态 S**（比如 7B 模型约 1-2GB，且与上下文长度无关）。无论你聊 100 句还是 10000 句，内存占用不变。

| 项目 | Transformer | RWKV |
| --- | --- | --- |
| 每轮新增内存 | 新增每个 token 的 K/V | 无（状态原地更新） |
| 长对话表现 | 越聊越慢，可能内存耗尽 | 速度、内存恒定 |
| 单次生成延迟 | 随上下文增长 | 恒定 |
| 极端长上下文 | 容易 OOM 崩溃 | 稳定可续 |

![多轮对话稳定性对比](img/fig22_speed_stable.png)

### 6.4.3 实战含义

对"多轮长对话"这类场景，差别是**能不能用**的区别：RWKV 聊到第 100 轮和第 1 轮一样快；Transformer 则在某轮开始后逐轮变慢，最终显存耗尽报错。这也是我们后续要把它套用到"AI 陪伴 / 情感智能体"上的核心原因之一。

## 6.5 训练方式对比：都支持并行，但代价不同

### 6.5.1 Transformer：天然并行

自注意力对序列内所有 token 同时计算，训练时 GPU 可以"全开"，所以训练效率极高。这是它统治大模型时代的核心竞争力。

### 6.5.2 RWKV：双模式并行

RWKV 的巧妙之处在于"同一套权重，两种跑法"：

- **训练（GPT 模式）**：把整段序列"摊开"，利用 WKV 的可分解性（前缀和），一次性并行算出所有位置的输出 → 训练速度和 Transformer 相当；
- **推理（RNN 模式）**：一个词一个词走，每步更新状态 → 内存固定、延迟恒定。

![双模式：训练并行 / 推理循环](img/fig11_dual_mode.png)

### 6.5.3 训练显存对比

因为 RWKV 不需要保存"每个 token 的 K/V 用于反向传播"（Transformer 训练时要保存大量中间激活），RWKV 的训练显存通常明显低于同规模 Transformer，这让**单卡微调**变得可行。

| 训练维度 | Transformer | RWKV |
| --- | --- | --- |
| 序列并行 | 支持 | 支持（GPT 模式） |
| 反向传播中间量 | 大（每层每 token） | 相对小（状态式） |
| 单卡微调友好度 | 一般（常用 LoRA） | 好（显存更低） |
| 长序列训练 | 昂贵 | 更省 |

## 6.6 效果对比：谁更强？

"谁更强"不能脱离场景和规模。客观地看：

### 6.6.1 RWKV 的强项

- **多语言**：RWKV-7 在 3B 规模的多语言 benchmark 上刷新 SOTA，非英语语言尤其突出；
- **状态追踪类推理**：RWKV-7 论文证明它能完成"状态追踪"、识别所有正则语言，理论上能表达超出 Transformer 受限复杂度类（TC0）的一些任务；
- **少样本学习（in-context learning）**：RWKV-7 是一个"元上下文学习器"，在每个 token 上对状态做"上下文梯度下降"式的自我调整；
- **稳定长程依赖**：因指数衰减+Token Shift，长文本的连贯性表现稳定。

### 6.6.2 Transformer 的强项

- **极致长上下文的精确回忆**：能精确引用任意位置的原文；
- **复杂推理 benchmark（如某些数学、代码题）**：在超大模型规模下，Transformer 生态更成熟、效果天花板更高；
- **生态成熟度**：训练框架、算子、工具链、文档、第三方支持都远超 RWKV。

### 6.6.3 一句话选型

| 你的诉求 | 推荐 |
| --- | --- |
| 要最先进效果、算力充足、不在乎成本 | Transformer |
| 长对话、低显存、边缘部署、成本敏感 | RWKV |
| 要私有化、离线、可控 | RWKV（更省） |
| 要丰富生态、成熟工具链 | Transformer |
| 低成本做个性化微调 | RWKV（显存低 + State Tuning） |

| 维度 | Transformer | RWKV |
