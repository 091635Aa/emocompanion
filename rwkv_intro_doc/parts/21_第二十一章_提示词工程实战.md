# 第二十一章 提示词工程实战：让 RWKV 更听话

"模型强不强"一半看模型，一半看**你怎么问**。这一章专门讲 RWKV 的提示词（Prompt）工程技巧——从基础结构到 RWKV 的专属玩法，让你花最小的成本，把模型效果榨到最好。

## 21.1 一条好提示词的四大要素

一个完整、有效的提示词通常包含：

| 要素 | 作用 | 示例 |
| --- | --- | --- |
| 角色（Role） | 设定身份与立场 | "你是一名温柔的心理咨询师" |
| 任务（Task） | 明确要干什么 | "请概括这段文字" |
| 约束（Constraints） | 限定格式/风格/边界 | "用 100 字以内，分三点" |
| 示例（Examples） | 给一个标准答案样板 | "例如：……" |

> **黄金结构**：`角色 + 任务 + 约束 + 示例`。四件套齐全，输出质量明显上升。

## 21.2 角色设定：RWKV 很吃这一套

RWKV 这类模型对"角色"非常敏感。同一个问题，加不加角色，效果天差地别：

```text
✗ 差：解释一下什么是焦虑。
✓ 好：你是一位有 10 年经验的心理咨询师。请用温柔、通俗的语言，向一位 20 岁的年轻人解释什么是焦虑，并给出 3 条缓解建议。
```

角色越具体，输出越"入戏"、越稳定。这对我们后面做 AI 陪伴（第十二章）尤其重要。

## 21.3 格式约束：让输出"可控"

想让输出变成 JSON、列表、表格，直接说清楚：

```text
请分析下面这段话的情绪，只输出 JSON：
{"emotion": "<开心/平静/难过/焦虑/愤怒/疲惫>", "confidence": <0~1>}

文本：今天工作被领导骂了，好烦。
```

输出：

```json
{"emotion": "焦虑", "confidence": 0.85}
```

> **技巧**：明确给出"输出格式模板"，比只说"结构化输出"有效得多。

## 21.4 少样本（Few-shot）：给几个例子胜过千言万语

给模型 1-3 个"输入 → 输出"示例，它就能模仿你的格式和风格：

```text
把口语转成书面语：

口语：那啥，明儿咱们去逛个街呗？
书面语：明天我们一起去逛街，好吗？

口语：这事儿我觉得吧，其实也没啥大不了的。
书面语：我认为这件事其实并不严重。

口语：你等会儿，我马上来。
书面语：
```

模型会自动顺着你的"例子风格"继续，产出高度一致。

## 21.5 RWKV 专属提示词技巧

### 21.5.1 技巧一：状态式思考，善用"记忆"

RWKV 有状态记忆，多轮对话时**不需要把历史再抄一遍**。系统提示词里放"长期人设"，每轮只放"本轮增量"：

```text
# 系统提示词（只设一次）
你是小暖，温柔耐心的 AI 伙伴。你记得用户的喜好和过往。

# 每轮只传当前消息（状态自动带着记忆）
用户：我今天有点难过……
```

这比 Transformer 的"每轮把整段历史重发"更省、更自然。

### 21.5.2 技巧二：用 State Tuning 固化人设

如果提示词太长（占大量 token），或者人设总是不稳定，就该上 **State Tuning** 了：把人设"训练进状态"，提示词就可以大大缩短，甚至只留一句"你是小暖"。

### 21.5.3 技巧三：善用"思考模式"开关

RWKV-7 G1 默认带思考模式（`/set think` / `/set nothink`）：

- **要严谨回答**（数学、代码、推理）→ 开思考模式；
- **要快速闲聊**（陪伴、接话）→ 关思考模式，更快更省。

### 21.5.4 技巧四：重复惩罚对抗"车轱辘话"

陪伴类对话里模型容易重复，除了调 `repetition_penalty`，提示词里也可以写：

```text
请避免重复用词和句式，不要复读之前说过的话。
```

## 21.6 常见提示词误区

| 误区 | 表现 | 改正 |
| --- | --- | --- |
| 提示词太短 | 输出泛泛而谈 | 补上角色 + 约束 + 示例 |
| 要求太多 | 顾此失彼 | 一次只聚焦 1-2 个要求 |
| 措辞模糊 | 输出跑偏 | 用"具体"代替"大概" |
| 提示词超长 | 占上下文、易被稀释 | 精简，或转 State Tuning |
| 忘记约束输出格式 | 解析困难 | 给出明确格式模板 |

## 21.7 提示词模板库（直接抄）

### 模板一：通用助手

```text
你是一个友好、专业的中文 AI 助手。请直接、简洁地回答问题，不要啰嗦。
问题：{问题}
```

### 模板二：总结提炼

```text
请把下面这段文字概括为 {N} 个要点，每个要点不超过 {M} 字，用编号列表输出：
{文本}
```

### 模板三：角色扮演 / 陪伴

```text
你是 {角色名}，性格 {性格描述}。说话风格：{风格}。
规则：先共情，再回应；不要长篇大论说教。
用户说：{消息}
```

### 模板四：结构化抽取

```text
从下面文本中抽取 {字段列表}，输出 JSON：
{文本}
```

## 21.8 提示词调优流程（方法论）

1. **先写出基线提示词**（角色+任务+约束+示例）；
2. **跑 5-10 个测试用例**，记录失败点；
3. **定位问题**：是缺角色？缺示例？还是约束不清晰？
4. **针对性修改**，一次只改一处；
5. **回归测试**，确认没改坏其他用例；
6. 反复迭代，直到稳定。

> **提示词工程是"低成本迭代"**：不用重新训练，几行字就能显著提升效果。先把它做到极致，再考虑微调/State Tuning。
