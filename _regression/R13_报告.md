## 2. 覆盖明细（R13）

在已有的「消费者侧 `接口 == '…'` 比较字面量须落在规范三元组 `{本地, logprobs, 提示}`」之上，补齐生产侧两个方向：

1. **return 唯一产出**：全 KV 核心目录扫描 `return '本地'/'logprobs'/'提示'`，断言这些模式名仅由 `接口降级.py` 的 `判定接口()` 产出，任何其它解码器文件 return 模式名即判定为逻辑漂移。
2. **回归中排除误报**：调试时发现 `锚点解码器(..., 接口="本地", ...)` 为**构造调用关键字实参**（消费端合法配置），与"模块级全局 `接口` 变量赋值"语义不同，需区分对待——本轮据此校准正则，确保护栏只盯真正的漂移而非误伤合法传参。

### 校准过程（含技术判断）

- 初版用 `接口\s*=\s*['"]` 匹配**所有** `接口=值`，立即在 `混合锚点器.py` 撞出 `接口="本地"`。
- 分析确认该处是 `锚点解码器(...)` 的命名实参，是把合法模式名**配置**给子解码器，不属于"第二来源重定义"。若放任会把护栏造成假阳性。
- 修正为两类正交检测：
  - **消费者**（3b）：`接口 == '…'` 比较字面量 ∈ 规范三元组。
  - **生产者**（3c）：`return '…'` 产出者 = `接口降级.py` 唯一。
