## 二、架构：算法栈从 transformers 完整移植到 llama.cpp

```
旧栈 (transformers + bnb4):          新栈 (llama.cpp CUDA + Q4_K_M):
  加载嵌入表 V×d 占内存              构建期预计算 bias (仅 600KB)
  LogitsProcessor 每步调 bias        PersonaLayers 每步调 bias (numpy 稀疏加减)
  依赖 torch/transformers 重栈       零 transformers 运行时依赖
```

**三层算法全部保留并在 vocab 维 logits 上实现**：
- **L1 去AI腔**：正例词袋 boost (21 tok + 15 短语) + 空泛词抑制 (33 tok + 33 短语)
- **L2 P3 锚点**：`logits += β·tanh(S·v_target/T)`，bias 预计算为 151936 维向量
- **OOC 拦截**：10 条身份泄漏短语硬抑制（强度 2.5）

## 三、性能对比（同 prompt、同 max_new=64）

| 指标 | 旧栈 bnb4 (transformers) | 新栈 llama.cpp | 提升 |
|------|--------------------------|----------------|------|
| decode tok/s | 10.0 | **27.3~33.8** | **+173%~238%** |
| 模型加载 | 259.9s | **2.2~3.9s** | **-98.5%** |
| 进程内存 | ~5-6GB (torch+bnb) | **2.8GB** | 显著下降 |
| 模型显存 | 2.81GB (bnb4) | ~2.5GB (Q4_K_M) | 相当 |
| transformers 依赖 | 必需 | **零运行时依赖** | 架构简化 |
| 首包延迟 | 秒级 | **4.24s (64 tok, 含RVC争用)** | — |

> 注：当前实测 15.2 tok/s 受后台 RVC 进程占显存影响（模型部分卸载）；释放显存后 llamba-bench 全卸载 33.84 tok/s（+238%）。

## 四、一键启动验证

`python app.py` 完整流程（实测通过）：
1. 检测 `.venv` → 无则 `python -m venv` 创建
2. 探测缺依赖 → 清华镜像自动安装（fastapi/uvicorn/psutil/jinja2/numpy）
3. llama_cpp CUDA 版由 pykits 提供（PYTHONPATH 注入，不重复装）
4. 设 CUDA 运行时 PATH → 启动 FastAPI
5. `/health` 返回 ok，模型加载 2.2s

双击 `启动缘圆引擎.bat` 即可一键运行。
