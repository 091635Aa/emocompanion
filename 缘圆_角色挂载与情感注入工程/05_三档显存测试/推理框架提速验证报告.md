## 3. 方案与踩坑记录

### 3.1 技术选型
- **推理框架**：llama.cpp（官方预编译 b10502，CUDA 12.4 后端）
- **模型格式**：Qwen3-4B Q4_K_M GGUF（官方仓库下载，sha256 校验通过）
- **Python 绑定**：llama-cpp-python 0.3.47（JamePeng fork，支持动态 CPU 后端）

### 3.2 关键坑：预编译 wheel 在 Zen3 CPU 崩溃（0xc000001d）
- **现象**：abetlen 官方 cu124 wheel（0.3.35）加载模型时 `OSError 0xc000001d`（STATUS_ILLEGAL_INSTRUCTION），CPU/GPU 全配置均崩溃。
- **根因**：预编译 wheel 在支持 AVX-512 的 CI 上按 AVX-512 编译，`ggml_cpu_init` 执行 `kmovd` 等指令；Ryzen 9 5900HX（Zen3）不支持 AVX-512，运行时非法指令崩溃。与 GPU 无关（CPU-only 同样崩溃）。
- **解决**：改用 `JamePeng/llama-cpp-python` fork 的 0.3.47 wheel —— 从 0.3.39 起用 `GGML_BACKEND_DL + GGML_CPU_ALL_VARIANTS` 编译，运行时按 CPU 能力动态加载兼容后端（haswell/sse42/zen4 等），彻底解决 Zen3 兼容问题。
- **佐证**：llama.cpp 官方 b10502 二进制同样动态加载 `ggml-cpu-haswell.dll`，Zen3 直接可用。

### 3.3 网络加速
- 通过桌面 GitHub 加速 VPN（局部模式）恢复 GitHub/HF 访问。
- GitHub release 大文件直连慢（0.07MB/s），改用 gh-proxy.com 加速镜像（≈3.5MB/s）下载官方二进制与 fork wheel。
- 中文路径导致 llama-bench 无法加载模型，用 d:\llama_models 英文路径硬链接解决。

## 5. 下一步建议
1. 关闭 RVC 等后台进程释放显存，全卸载后可稳定 33+ tok/s（+238%）。
2. 将情感注入算法（P3 锚点等 logits 层）移植到 llama.cpp 采样器钩子，验证解码期注入仍可达标。
3. 长上下文场景建议 n_ctx 调至 4096，用 KV cache 量化进一步降显存。
