# 全流程实测报告（7B4B · 多尺寸 × 基线/P3 锚点注入）

> 环境：RTX 3080 Laptop 16GB（WDDM）｜ Python3.10｜torch2.5.1+cu121｜transformers4.57.6｜bitsandbytes0.50
> 被测模型：Qwen2.5-0.5B、Qwen3-0.6B、SmolLM2-1.7B、gemma-2-2b、Phi-3.5-mini、**Qwen3-4B(4bit)**、**DeepSeek-R1-Distill-Qwen-7B(4bit, 即 Qwen2-7B)**、**Qwen3-8B(4bit)**
> 算法：baseline 裸采样 vs **P3 锚点回响**（情感方向注入 `logits+=β·tanh(cos(emb_tok,锚点)·v_角色/T)`，零权重、只读词嵌入；目标方向=缘圆人格：温柔/开心/撒娇，压制难过/紧张）
> 指标：语义熵(顶1k近似)、2-gram重复率、cnsenti正/负情绪词量、目标情感词命中、吞吐、峰值显存。
> 复现：`run_sweep.py`（健康指标）、`run_judge.py` + `judge_unbiased.py`（LLM裁判）

## 二、能下的结论（客观、可复现）

1. **无坍缩、无复读/OCR 式退化**：注入后无一模型熵崩到 <1 的锁死态；绝大多数模型 2-gram 重复率**下降**（更不机械），7B 从 0.186→0.122、8B 熵大幅升。
2. **Qwen 系 + SmolLM 受益明显**：熵升 + 重复率降 + 4B/0.6B 正向情绪词显著增（31/7→54/11、24/8→37/8）→ "情感方向挂载"确实把输出往缘圆(温柔/开心/撒娇)牵引。
3. **7B4B 头部达标**：DeepSeek(7B,Qwen2) 4bit 注入后熵 1.31→1.72、重复率降，吞吐 14.6 token/s 稳定，峰值 9.5G（含一次性锚点构建瞬时），远高于 3–5 tok/s 下限。
4. **架构敏感证实（关键工程结论）**：同样固定 β=0.5，**gemma-2-2b 明显过注入**（重复率 0.081→0.226），Phi/0.5B 增益有限——印证家族"hidden_dim 同≠最优 λ 同、需架构族因子"规律。**这正说明方案里 P1.5 架构族×量化(4bit×0.75) 调度器是必需的**，固定参数不可全量产。

## 三、显存/资源观察

- 峰值显存里含"锚点表一次性构建"瞬时开销（我把词嵌入 `.float()` 后算余弦，7B 该瞬态约 +2GB）。稳态生成更低；把该计算放 CPU（方案 §7.2）即可压到 <1GB 情感开销预算。
- 8B 峰值 10.6G > 8G 目标；7B(9.5G) 与 4B 才合 8/10/12G 三档。→ **8GB 主目标正确落在 4B 与 7B，8B 归 16G 档**。

## 四、LLM 裁判（快评）与诚实校正

- Qwen3-8B 初评 P3 10/10 全胜 → **判定为位置偏置伪影**：裁判几乎恒选第二个选项"B"。去偏置(随机交换 A/B)后 P3"胜率"= {P3 恰好放在 B 位的比例}=70%，仍是位置偏好，非内容判别。
- **因此"准确率/更像真人"一栏本次不给分**。根因：① 裁判固定选 B；② 被测输出是「无对话模板直接续写」，模型跑偏成翻译/QA/思考，并非真正的缘圆角色扮演对话，本身不达标。
- 结论：**要拿到可信的 LLM-Judge 赢率，必须**：用 chat 模板做真实角色扮演生成 + 样本量 30~60 + 裁判 AB 双投/位置消除 + 7B 档换用 **instruct（Qwen3-8B）而非 reasoning（R1）**。这正是家族已验证的 EmoCharacter/LLM-Judge 评估线，本实测不越级宣称。

## 五、"拉到较高水准"的现实动作

1. 7B 档位主推 **Qwen3-8B-Instruct (4bit)**（instruct、中文情感强、8B 熵提升明显），弃用 R1（reasoning 不适合角色直播）。
2. P3 注入强度按 **架构族调度**：Qwen 系可直接固定；gemma/Phi 需 ×0.5~0.7（P1.5 因子）；再叠加 4bit×0.75 → 全尺寸可把重复率过注拉回健康区间。
3. 锚点表构建移 **CPU**，GPU 仅按步取 V×1 偏置 → 情感注入显存开销趋近 0，把 7B 峰值压回 <7G。
4. 角色还原度走 **EmoCharacter + LLM-Judge(校准后)** 正式基线（30~60 样本、chat 模板角色扮演）。
