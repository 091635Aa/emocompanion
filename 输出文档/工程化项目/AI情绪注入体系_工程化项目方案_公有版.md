## 一、项目背景与目标

### 1.1 背景

大语言模型（LLM）在角色对话、情感陪伴、虚拟主播、智能客服等场景需要稳定地表达"带有特定人设与情绪"的语言。业界主流做法（微调、提示词）存在成本高、不可热切换、效果不稳、AI 腔明显等短板。本项目将一套 **无需训练的解码期情感注入技术体系** 工程化，封装为可嵌入各类产品的"情感注入引擎"（Emotion Injection Engine, EIE）。

### 1.2 目标

1. 提供可复用的跨平台 SDK，CPU/低显存可实时运行（推理 ≥27 tok/s）；
2. 角色包 ≤10MB，支持运行时指针级热切换（<1ms）；
3. 对宿主应用零侵入：不修改模型权重、零额外显存、μs 级额外开销；
4. 具备完整的质量监控、五级降级、合规安全（身份拦截/防沉迷接口/危机干预）；
5. 输出"角色构建→离线提取→在线注入→效果评测→合规审计"全链路工程工具链。

### 1.3 非目标（明确不做）

- 不做模型训练/微调；
- 不含语音合成、情感识别等外围模块的实现细节（仅定义对接接口）；
- 此文档为公有版，不含私有品牌名与未公开的商业参数。

│         角色包仓库（离线产物）                              │
│  role_pack.json / bias.npy / emotion_vectors.npy /         │

└─────────────────────────────┬─────────────────────────────┘

┌─────────────────────────────▼─────────────────────────────┐
│         离线管线（构建与评测工具链）                        │

**架构原则**：离在线分离（离线构建角色包，在线只读加载）；正交空间隔离（各注入层互不放大）；调度统一（全局强度预算 ≤2.5）；安全兜底（五级降级 + 身份拦截）。

## 三、模块划分与依赖

### 3.1 模块清单

| 模块 | 职责 | 类型 | 关键依赖 |
|------|------|------|---------|
| `engine` | 解码期 logits/注意力/KV 注入内核 | 核心 | numpy、llama-cpp-python（后端可选） |
| `scheduler` | 强度调度/监控/熔断/降级 | 核心 | 无外部依赖（纯计算） |
| `rolepack` | 角色包加载/热切换/缓存 | 核心 | 文件 I/O、JSON/Aligned 读取 |
| `builder` | 离线特征提取与打包 | CLI | numpy、jieba、可选 librosa/pyworld |
| `eval` | 效果评测（客观指标 + LLM-Judge） | CLI | numpy、OpenAI 兼容 API（可选） |
| `api` | REST 服务（FastAPI） | 服务 | fastapi、uvicorn（可选） |
| `audit` | 合规日志 / 风险词扫描 / 危机事件钩子 | 核心 | 无（纯规则） |

### 3.2 依赖策略

- **最小运行时依赖**：numpy（固定版本）+ 宿主推理引擎接口（`llama-cpp-python` 及兼容者）；
- 音频、双模态、LLM-Judge 均为可选依赖，按场景 `pip install eie[extra]` 安装；
- 全部模型文件放置于英文目录（规避路径解析问题），路径通过配置注入；
- 国产环境依赖镜像安装（如清华源），离线安装包随版本发布。

## 四、关键接口定义（公有版）

### 4.1 角色包格式（v1 基线）

| 文件 | 格式 | 说明 |
|------|------|------|
| `role_pack.json` | JSON | 元数据：id、名称(通用)、情感配比、参数 |
| `bias.npy` | float32 | vocab 维偏置向量（约 3.6MB） |
| `emotion_vectors.npy` | float32 | 情感向量表（可选） |
| `positive_bag.json` | JSON | 角色口癖正例词袋 |
| `hollow_weighted.json` | JSON | 空泛/AI腔抑制表+短语 |
| `manifest.sha256` | 文本 | 完整性校验 |

### 4.2 SDK 核心接口

```python
class EIE:
    def __init__(self, model_backend, config): ...
    def load_role_pack(self, path) -> str: ...          # 热切换
    def process(self, logits, ctx) -> logits: ...       # 每步注入
    def get_state(self) -> dict: ...                    # 监控/调度状态
    def shutdown(self): ...
```

**REST（可选）**：`POST /eie/inject`、`POST /eie/roles/load`、`GET /eie/health`、`GET /eie/stats`。

### 4.3 回调事件（供宿主处理合规）

- `ON_RISK`：检测到高风险情绪（如自残表述）→ 宿主接入人工/危机干预；
- `ON_OOC`：身份出戏拦截发生 → 记账审计日志；
- `ON_OVERLOAD`：连续异常触发熔断 → 通知宿主降级策略。

- AI 腔率 ≤15%、保真度 ≥74%（mild 基线）；
- 合规用例（OOC 触发、风险词、防沉迷钩子）全部通过。

## 七、合规与安全设计（公有口径）

1. **AI 标识透明化**：宿主在交互界面固定显示"AI 互动标识"（≥16 号，对比度 ≥3:1）；自我介绍模板统一为"I 是 AI"合规话术；
2. **防沉迷**：连续使用提示/超时锁定/22:00-07:00 工具模式切换——通过回调事件与配置项供宿主实施；
3. **未成年人保护**：年龄验证钩子、监护人授权接口、内容分级白名单——SDK 提供拦截位；
4. **风险干预**：ON_RISK 事件 + 安抚话术库 + 引导求助；日志留存 ≥6 个月（由宿主执行）；
5. **身份硬拦截**：OOC 检测（自我认知/角色破裂/元讨论三类）+ 强度可配置（默认 2.5）；
6. **数据最小化**：本地存储优先，上传仅脱敏摘要（联邦/授权同步由宿主落地）。
