# 克隆方案调研（任务 5.1）

调研时间：2026-08-01
用途：为 `音色注册.py` 的 `注册()` / `克隆()` 确定 DashScope 声音复刻接口的请求体与参数。

## 一、结论速览

| 方案 | 复刻模型（model） | action | 音频参数 | 名称参数 | 返回音色字段 | 绑定模型（target_model） |
| --- | --- | --- | --- | --- | --- | --- |
| A. Qwen-Audio-TTS / CosyVoice 复刻 | `voice-enrollment` | `create_voice` | `url`（官方要求公网 URL；`audio.data` base64 直传为实测可行） | `prefix`（仅字母数字，≤10 字符） | `output.voice_id` | `qwen-audio-3.0-tts-plus` / `qwen-audio-3.0-tts-flash` / `cosyvoice-v3.5-plus` 等 |
| B. Qwen-TTS 复刻（官方推荐 base64 直传） | `qwen-voice-enrollment` | `create` | `audio.data`（data URI：`data:{mime};base64,...`，支持 audio/wav、audio/mpeg、audio/mp4） | `preferred_name` | `output.voice` | `qwen3-tts-vc-2026-01-22` |
| C. Qwen3.5-Omni 复刻（few-shot 克隆） | `qwen-voice-enrollment` | `create` | 同 B（上传一段 10~20 秒录音即克隆，无需训练） | `preferred_name` | `output.voice` | `qwen3.5-omni-plus` / `qwen3.5-omni-flash` / `qwen3.5-omni-plus-realtime` / `qwen3.5-omni-flash-realtime` |

**统一端点**：`POST {接入地址}/services/audio/tts/customization`（`接入地址` 即 `语音合成.接入地址()`，默认 `https://dashscope.aliyuncs.com/api/v1`）。

**关键原则**：`target_model`（绑定模型）必须与后续调用语音合成接口时使用的模型完全一致，否则合成失败。

## 二、接口参数详解

### 方案 A：Qwen-Audio-TTS / CosyVoice 声音复刻（`voice-enrollment`）

```json
{
  "model": "voice-enrollment",
  "input": {
    "action": "create_voice",
    "target_model": "qwen-audio-3.0-tts-flash",
    "prefix": "myvoice",
    "url": "https://your-audio-url.wav"
  }
}
```

- `url`：音频文件 URL，**官方要求公网可访问**。
- `prefix`：音色名称前缀，仅允许数字和英文字母，不超过 10 个字符；生成音色名格式 `{target_model}-{prefix}-{唯一标识}`。
- 可选参数（SDK `VoiceEnrollmentService.create_voice`）：
  - `language_hints: List[str]`：仅 CosyVoice 复刻支持，辅助语种识别，默认 `["zh"]`。
  - `max_prompt_audio_length`：复刻参考音频最大时长（秒），范围 [3.0, 30.0]，默认 10.0。
  - `enable_preprocess`：是否开启音频预处理（降噪/增强/音量规整），默认 false。
- 返回：`output.voice_id`。
- 备注：旧工程 `voice_clone_work/enroll_voice.py`、`upgrade_voice.py` 实测把 base64 data URI 放进 `audio.data` 或 `url` 字段可以成功注册（`voice_id.txt` 已有成功注册的 voice_id：`qwen-audio-3.0-tts-plus-yuanyuan-c6cf949d19734ab5a5552a9c5ce2da9f`），故本模块保留 base64 直传方案（`audio.data` → 备选 `url` 字段）作回退。

### 方案 B：Qwen-TTS 声音复刻（`qwen-voice-enrollment`，官方示例即 base64 直传）

```json
{
  "model": "qwen-voice-enrollment",
  "input": {
    "action": "create",
    "target_model": "qwen3-tts-vc-2026-01-22",
    "preferred_name": "guanyu",
    "audio": {"data": "data:audio/mpeg;base64,..."}
  }
}
```

- `audio.data`：两种提交方式：
  1. **Data URL（Base64 编码，本模块采用）**：`data:{mime_type};base64,{base64}`，MIME 支持 `audio/wav`、`audio/mpeg`、`audio/mp4`。
  2. 音频 URL：`{"data": "https://your-audio-url.wav"}`（公网可访问、无需鉴权）。
- `preferred_name`：音色名称（相当于方案 A 的 `prefix`）。
- 可选 `text`：音频的文本转写，用于提升复刻质量。
- 返回：`output.voice`（注意字段名是 `voice` 而非 `voice_id`）。

### 方案 C：Qwen3.5-Omni 声音复刻（few-shot 克隆，"上传录音即克隆"）

- 复刻模型仍为 `qwen-voice-enrollment`，请求体与方案 B 完全一致，仅 `target_model` 换成 Omni 系列：`qwen3.5-omni-plus`、`qwen3.5-omni-flash`、`qwen3.5-omni-plus-realtime`、`qwen3.5-omni-flash-realtime`。
- **结论：没有独立的"few-shot 克隆"对话式接口**——Omni 的克隆复用方案 B 的 create 接口，上传一段 10~20 秒录音即可克隆音色，无需训练，故 `克隆()` 按方案 B/C 实现。
- 返回：`output.voice`。

## 三、音频要求（各方案通用，直接决定筛选器硬约束）

| 项目 | 要求 |
| --- | --- |
| 支持格式 | WAV (16bit)、MP3、M4A |
| 音频时长 | 推荐 10~20 秒，最长不得超过 60 秒 |
| 文件大小 | < 10 MB |
| 采样率 | ≥ 24 kHz |
| 声道 | 单声道 |
| 内容 | 至少 3 秒连续清晰朗读（无背景音），其余部分仅允许短暂停顿（≤2 秒）；避免背景音乐、噪音或其他人声；请使用正常说话音频，不要上传歌曲/唱歌 |
| 语言 | zh/en/de/it/pt/es/ja/ko/fr/ru/th/id/ar/cs/da/nl/fi/he/hi/is/ms/no/fa/pl/sv/tl/tr/ur/vi 及中文方言 |

> 本项目筛选器硬约束（语音占比 ≥ 0.55、最大连续停顿 ≤ 2.0s、最终 10~20s、24kHz 单声道）正是为满足上表而设计。

## 五、本模块采用的注册策略

1. **首选（方案 A · base64 直传）**：`voice-enrollment` / `create_voice` / `prefix` / `target_model=qwen-audio-3.0-tts-plus` / `audio.data`（base64 data URI），备选 `url` 字段同样填 data URI。
   —— 与旧工程实测成功方案一致，且绑定模型 `qwen-audio-3.0-tts-plus` 与 `质量校验.py` 的试合成模型一致，注册成功后校验可直接通过。
2. **次选（方案 B/C · 官方 base64 直传）**：`qwen-voice-enrollment` / `create` / `preferred_name` / `audio.data`，`target_model` 默认 `qwen3-tts-vc-2026-01-22`（可切换为 Qwen3.5-Omni 系列）。
3. **克隆接口**：`克隆(录音路径, 声音库目录, 名称)` 直接采用方案 C（Qwen3.5-Omni，`target_model=qwen3.5-omni-flash`），供需要 Omni 音色的场景调用。
